三、万用表 66k 之谜（为什么 R8 在板测不是 220k）

现象

测量对象万用表读数标称值评价
R7 两端（VBAT ↔ ADC_BAT）99.6 kΩ（稳定）100 kΩ✓ 正常
R8 两端（ADC_BAT ↔ GND）65.4 kΩ（跳动）220 kΩ✗ 差 3 倍
注：用户最初报的是 66k；后续用另一副表笔复测为 65.4 kΩ（还量到 99.6 k）、以及 65.4 k / 99.6 k，结论不变。

答案：欧姆档测的是「并联等效电阻」，不是元件本身

数字万用表的欧姆档会在表笔间输出一个测试电压。当你把表笔搭在 R8 两端（ADC_BAT ↔ GND）时，测试电流有两条路径可走：

  1. 直接穿过 R8 到地 —— 220 kΩ
  2. 向上穿过 R7、再经 VBAT 网络（PMOS-Q1 的体二极管 / 电池直插支路）回到地 —— 这形成与 R8 并联的另一条通路
R8 在板读数 ≈ R8 ∥ (R7 + VBAT 侧等效阻抗)
           ≈ 220k ∥ 100k        ← VBAT 侧近似低阻（PMOS 体二极管 / 直接短接 V33）
           = 68.75 kΩ
实测 65.4 kΩ ≈ 68.75 kΩ（差值来自电阻公差 + 表笔接触电阻 + C14 充放电导致的读数抖动）

为什么 R7 却测出来很准？

测 R7 时，测试电压加在 VBAT ↔ ADC_BAT 之间。ADC_BAT 往下是 R8 + C14 到地，R8 是 220 kΩ 远大于 R7 的 100 kΩ，所以并联影响很小，绝大部分压降落在 R7 上 ⇒ 读数接近真实 100 k。

结论：R8 在板测出 65～66 kΩ 是完全正常的测量假象，器件没坏。要量真实值必须把电阻焊下来（或至少断开一端）。同理 验证 R8 真实值的最佳手段是「电压法」：见下方第四章的实测电压核对。

四、调试短接 V33 的连锁影响

调试动作（用户说明）：「为了调试，VBAT 直接接到 3.3，因为不这样做的话不连接电池，4G 模组无法供电。」
⇒ 板上 CN3142 充电 → VBAT → LDO ME6206A33XG → VCC33 这条正常链路中，LDO 的输出被 VBAT 旁路跨过，VCC33 网络实际电压 = VBAT ≈ 4.0~4.2 V。

3.1 RC 时间常数到底是多少、旧注释错在哪

旧注释原文（git 7a52ac9:Core/Src/main.c）：
② 等 ≥2 ms 让 R7(100k)+R8(220k) 与 C14(100nF) 的 RC 稳定
   （τ = 100k ∥ 220k × 100n ≈ 6.9 µs，2 ms 余量足够）   ← 数字对、单位错
项目旧注释（错）正确
源阻抗100k∥220k100k∥220k = 68.57 kΩ（写对了）
电容C14 = 100 nFC14 = 100 nF（写对了）
τ 单位6.9 µs6.86 ms （差了 1000 倍）
「余量」判断2 ms 足够2 ms 只有 0.29τ，远不够
为什么是 ms 不是 µs：数量级自检 —— kΩ × nF = 10³ Ω × 10⁻⁹ F = 10⁻⁶ s = µs？错！ 再算一遍：68.57×10³ × 100×10⁻⁹ = 68.57×100 × 10⁻⁶ = 6857×10⁻⁶ s = 6.857 ms。
关键在 系数：kΩ×nF 得到的单位确实是 µs，但只是「数值上 1 kΩ·nF = 1 µs」这个速记本身要求电阻电容量级配套。
——真正的坑不是量纲，是旧注释把 68.57×100 算成了「6.9」：应得 6857（单位 µs）＝ 6.857 ms，却被写成 6.9 又贴上 µs 标签，等于把结果整整缩小 1000 倍。
一句话记牢：τ[ms] ≈ R[kΩ]·C[µF]，或 τ[µs] ≈ R[Ω]·C[µF]。本电路 68.6 kΩ × 0.1 µF = 6.86 ms。

⇒ RC 等待不足，是三个缺陷里影响最小的一条（约 ±1.8% / 40 mV）；真正的大头是 ① 基准假设 3.3 V（实为 4.17 V，−20%）和 ② PA2 极性反（支路切断，读到浮空残荷）。
但 50 ms ≈ 7.3τ 后误差 e^-7.27 ≈ 0.07%，属于「一劳永逸、不留隐患」的写法，代价仅 50 ms 阻塞。

4. 附带修掉的致命 bug

main() 从未调用 MX_ADC1_Init()（CubeMX 生成后漏接）⇒ hadc1.Instance == NULL ⇒ 首次采样时 HAL_ADC_Start → ADC_Enable() 去写 NULL->CR2（地址 0x24）⇒ IMPRECISERR 总线错误（CFSR=0x00000400）→ HardFault 整板死机。
症状极具误导性：SWD 注入命令后 g_test_go 永不归零、_4g_state 停在残值 0x0E（看着像 READY，其实 CPU 早死了）。
诊断路径：ICSR(0xE000ED04) 低 9 位 = 异常号（3 = HardFault）→ CFSR(0xE000ED28) bit10 = IMPRECISERR → HardFault 栈帧取第 7 字 = 出错 PC → arm-none-eabi-addr2line 反查。
修法：main 里补 MX_ADC1_Init(); + bat_adc_sample() 开头加空指针防御。

六、测量方法与踩坑

SWD 注入脚本：每次都要现场解析符号地址
今天犯了两遍的坑：新增全局变量 g_vrefint_raw/g_vdda_mv 后，符号地址漂移 —— g_test_cmd 从 0x200007DC → 0x200007E0，g_test_go 从 0x2000080C → 0x20000810。脚本沿用旧地址 ⇒ 命令写进无效内存 ⇒ 读回全 0，白跑一轮。
arm-none-eabi-nm -n firmware.elf | grep -E "g_test_cmd|g_test_go|g_bat_|g_vdda"
铁律：SWD 注入脚本每次运行前先 nm 解析，绝不写死地址。
Flash 读保护（RDP）意外置位
动线/异常之后出现过 Error: stm32x device protected，烧录被拒。恢复步骤：
  1. openocd ... -c "init" -c "reset halt" -c "stm32f1x unlock 0"（会提示「需复位生效」）
  2. USB 继电器硬断电脉冲（COM12）：relay.cmd pulse --off-ms 3000
  3. 重新烧录，Verified OK
万用表 vs ADC 的差异说明
修复后 ADC 读节点 2814 mV，万用表早前测 R8 两端 2.7 V —— 差约 0.11 V，属正常：
  • VREFINT 标称分散 ±5%（1.20 V ±5%），是当前主要的绝对精度来源
  • 万用表多为 10 MΩ 输入阻抗，会与 68.6 kΩ 源阻抗形成轻微分压
  • 两次测量时刻不同，VBAT 随光伏充电状态浮动
所以「准确度」应理解为 ±5% 量级：足够判断电量档位（满 / 良好 / 偏低 / 低电），但不适合作为精密电压表。
欧姆档在板测电阻的通则
  • 板上任何电阻，只要两端还挂着其他通路，欧姆档读到的就是并联等效值，不是元件真值
  • 电容（如 C14）会让读数持续跳动 —— 欧姆档的测试电压在给电容充放电
  • 要量真值：焊下元件，或断开一端；更省事的办法是通电测电压再用分压/欧姆定律反推
