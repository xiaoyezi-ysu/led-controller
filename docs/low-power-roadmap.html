5. 续篇 · 怎么从 1.16 mA 走到 0.20 mA（三步，第一刀是「假 Stop」）

口径先对齐。第 1~4 节是 ver2 硬件 + 10-13 那版固件（下文称固件 v1）的路径； 本节加的是固件版本 v1 → v2 → v3 的改动（同一块 ver2 板，没换板、没改 BOM）。 这几个数别混着比：0.270 = 改前整板（CH1）、0.220 = 改前 MCU 支路（CH2）、 0.200 = 改后整板（CH1）、0.14~0.17 = 改后 MCU 支路（CH2）。 整板与支路之间还差一条 4G 支路（不走 LDO，无表，靠 KCL 减出来，且会漂 0~0.07 mA）。
⚠ 先纠一个旧结论：1.162 mA 那次「Stop」其实没真进 Stop（是 Sleep）。 当时主循环每圈都会重写 SCB_SCR，SLEEPDEEP 被反复清掉，内核只进了 Sleep（≈2.2 mA）而非 Stop。 两者差一个数量级：Sleep 只是停下取指，内核/总线时钟照跑、外设寄存器照常可读；Stop 才把 1.8V 域全关，只剩 LSE + RTC 闹钟。 真实 Stop 要等 lp_cycle 由 RTC 闹钟驱动、让固件自己走完入睡流程才测得到 —— 那才是 0.225 mA。 正确的分解是：3.47 →（关 LEDB2 1.09）→ 2.38（Run）→（Sleep→Stop 1.99）→ 0.225。
⑤ 真进 Stop固件 v1 末 2.38 → 0.226 mA
F-11 中位 · 批次 20261013_2225 −0.94 mA（Sleep→Stop） ▸
方法 / 操作
  1. 主循环顶部删掉每圈对 SCB_SCR 的重写；只有 lp_cycle 决定入睡时才置 SCB_SCR |= 0x04（SLEEPDEEP）。
  2. 进 Stop 前过门禁 RTC_APP_WakeArmed()：同时校验 ALR 回读 + CRH.ALRIE + NVIC->ISER[1] bit9（RTC_Alarm_IRQn = 41），缺一拒绝下睡。
  3. 测之前先把 DBGMCU_CR(0xE0042004) 清 0 —— OpenOCD 每次 init 会写 0x307，睡态虚增 0.82 mA。
  4. WFI 入睡 → RTC 闹钟唤醒 → HAL_ResumeTick() + SystemClock_Config()（Stop 退出后 SYSCLK 回落 HSI，不重配则波特率全错）。
  5. 判据：AHB/APB 外设寄存器整片读 0 才是真 Stop 指纹，uwTick 冻结；Sleep 下寄存器照常可读 —— 这就是当初误判的根源。
省下

1.162 → 0.226（Sleep→Stop）= −0.94 mA；若从 Run 2.38 算起 = −2.15 mA

风险 / 回滚

Stop 退出后 SYSCLK 回落 HSI，唤醒必须重跑 SystemClock_Config()，否则波特率全错、4G 失联

⑥ UART 引脚切模拟固件 v2 整板 0.270 → 0.200 mA
CH1 中位 · 10-20 凌晨 −70 µA
唯一做过 A/B 实测 ▸
方法 / 操作
  1. 新增 UART4G_PinsToAnalog()：PA9(TX1) / PA10(RX1) / PB3 / PB4 设为 GPIO_MODE_ANALOG（输入缓冲关断、输出级断开）。
  2. 三个进 Stop 入口都要调，位置在 V4G_Set(0) 之后：LP_CloseAndSleepEx()、SEQK_SLEEP、batlp 电池低压分支。
  3. 唤醒侧四个出口恢复 UART4G_PinsRestore()：PA9 → AF_PP、PA10 → INPUT_PULLUP（与 CubeMX USART1 初始化一致）。
  4. 唯一不恢复的是 batlp「继续睡」分支 —— 继续睡就该保持模拟输入，代码里专门标了注释。
  5. 验证：整板 0.270 → 0.200 mA，反复复位可复现。
原理

消除 3.3V 空闲高电平经模组 RX 脚 ESD 二极管往 V4G 轨的回灌。

风险 / 回滚

漏一个恢复出口 = 唤醒后 4G 连不上；batlp「继续睡」分支故意不恢复（继续睡就该保持模拟输入）

⑦ SC7A20H power-down固件 v3a 6~11 → 0.5 µA
数据手册推算，未单独 A/B −~8 µA ▸
方法 / 操作
  1. SC7A20H_PowerDown()：CTRL_REG1(0x20) 写 0x00，ODR=0000 → power-down ~0.5 µA。
  2. SC7A20H_WakeUp()：写回 0x47（50 Hz、低功耗模式、三轴使能）。
  3. 只在 g_sc7_id == 0x11 时执行（芯片不在就跳过），I2C 写失败静默无省电、不影响功能。
  4. 调用点同 UART：三个入睡入口各一次；唤醒恢复走统一出口。
风险 / 回滚

I2C 写失败就静默无省电，无功能风险；唤醒漏写回则无加速度中断

⑧ Stop 期 LPDS固件 v3b 14 → ~5 µA
F103 手册 typ，未单独 A/B −~9 µA ▸
方法 / 操作
  1. PWR->CR |= PWR_CR_LPDS，放在 RTC_APP_Init() 里一次设好（PWR 时钟随 BKP 一起已开）。
  2. Run / Sleep 不受影响，只有 Stop 生效 —— 代价是唤醒多几 µs，RTC 闹钟场景完全无感。
  3. 手册 typ：Stop 电流 14 → ~5 µA；因 4G 支路漂移比它还大，实测里切不出来，只能算「量级相符」。
风险 / 回滚

零风险（只是内部稳压器换低功耗档）

合计 · v1 → v3：①~④ + ⑤~⑧ 全部落地后，实测整板睡态 0.19 ~ 0.21 mA（CH1 中位 −0.207 / 最低 −0.215）。 省下：−70 µA 已证实（⑥），SC7+LPDS 理论再 −17 µA。 ⑥ 之外的归因只能到「量级相符」：4G 支路本身漂 0~70 µA，比 SC7+LPDS 合计还大，分辨不出来。
