3. 每步一览（方法 / 电流 / 风险）

步方法（怎么做的）达到的电流省下风险 / 回滚
① L1 SystemClock_Config() 关 PLL，HSE 8 MHz 直供，Flash 0 等待，HSI_DISABLE；宏 CPU_CLOCK_8MHZ 一行开关 22.5 → 10.5 mA
探针原始		 −11.8 mA
（−52%）		 零风险；注释宏即回滚；不碰 SWD / 选项字节
② 关 4G SWD 写 GPIOA_ODR 清 bit3（4 字节 0x04 0xA4 0x00 0x00）→ V4G 断电 59.40 → 3.47 mA
F-11 真值		 −55.9 mA 固件下次复位自动拉高 PA3，4G 回 ~60 mA
③ L2 DBGMCU_CR=0x02（保 SWD）+ SCB_SCR=0x04（SLEEPDEEP），主循环 WFI() 进 Stop 3.47 → 2.31 mA
F-11 真值		 −1.16 mA 进 Stop 后只能 EXTI / 复位退出（见下表）
④ 拆 R24 硬件断开 R24（510 Ω，串在 VCC33 与 LEDB2 之间）；或改由 GPIO 控制 2.31 → 1.162 mA
F-11 真值		 −1.15 mA 改板件；常亮在 Run / Stop 下耗电一样
⇒ 1 mA 量级达成。距 1.00 mA 还差 0.16 mA，来自 Stop↔唤醒往复抖动 + LDO 静态 / 漏电。 下一步：固件化 Stop（HAL_PWR_EnterSTOPMode() + EXTI 唤醒）并关掉非必要周期中断。

4. ⚠️ 遇到的问题（踩坑记录）与对策

阶段问题现象 / 代价解决方法
① 调试 mklink write-ram 重建整个 32 位字，未写字节被清零 写 CCR 高字节把 16 位寄存器清 0 → 误判「8 MHz 下 LED 不亮」；写 GPIOA_CRH 高字节打断 USART1 → 4G 通信断（42→12 mA） 多字段寄存器一次写满 4 字节，16 位寄存器只写低字节；误写后重新烧录恢复
③ 判定 探针 power-read 存在 ≈6 mA 零点偏置且漂移 曾把 8.20 mA 当成「无法解释的神秘固定负载」，方向几乎走偏 改用 F-11 真值表独立互证；每次对比前先测零点，绝对电流 = 读数 − 零点
③ 判定 进 Stop 后 AHB/APB 寄存器整片读 0 一度以为「寄存器被清零 / 固件挂了」，怀疑变砖 认作 Stop 指纹（内核私有区 SCB_SCR/DBGMCU_CR/SysTick 仍可读）；清标志后读数立即复原
④ 收尾 进 Stop 后清 SCB_SCR=0 出不来 电流卡在 1.94 mA 中间态（既非 Run 2.40 也非 Stop 1.16） Stop 只能被 EXTI 唤醒，内核异常（SysTick）无效；唯一可靠退出 = 复位（mklink reset / SW4），复位后未变砖
全程 mklink 从 PATH 漂没（command not found） 所有命令失败 用绝对路径 ...\envs\default\Scripts\mklink.exe
全程 电表 USB 掉线会切断被测回路 表一消失，板子立刻断电（idcode=0x0、电流退回零点） 测完不要随手拔 Type-C；表串在探针 VCC 与板子 VCC 之间
硬件 LEDB2 + R24 510 Ω 跨 VCC33 常亮，固件关不掉 常亮吃 ≈1.1 mA，1 mA 目标最大的单项拦路虎 硬件断开 R24（或改由 GPIO 控制）
