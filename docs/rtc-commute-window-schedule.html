0. 结论先说

① 进 Stop，不用 Sleep。 Stop 实测 0.226 mA，旧的低功耗 Sleep 模式是 2.22 mA（差 1.99 mA，因为 Sleep 只停内核时钟、HSE 与 AHB/APB 照跑）。 20 h 空闲段：Stop 只烧 4.5 mAh，Sleep 要烧 44.4 mAh —— 一天白送 40 mAh，没有任何好处。 而且 RTC 闹钟走 EXTI17，本来就只能唤醒 Stop，Sleep 反而用不上这套机制。
② 窗口内的引擎不用新写，直接复用已验证的 lp_cycle。 现有循环已经是「睡 → RTC 闹钟醒 → 联网/授时/上报 → 关 4G → 再睡」，实测 Stop 0.226 mA、每轮醒窗耗 4840 mA·s。 这次要加的只是「到什么钟点开关窗」这一层判断。
③ rtc_app.c 一行都不用改。 RTC_APP_ArmIn(delay_s) 的参数是 32 位秒，最长 12 h 的长睡（43200 s）远在量程内， ALR 比较值 = 当前计数 + delay，不存在 24 h 回绕问题。
④ 1000 mAh 对这个方案余量很大。 最坏点（早上 09:00、发电开始前）只亏 105 mAh ≈ 10.5% 放电深度； 日终反而净涨 202 mAh；连阴雨 3.8 天也扛得住。

3. 调度机制（在现有 lp_cycle 上加一层窗口判断）

收尾处的伪代码（改动集中在这一处）

/* main.c LP_CloseAndSleep() —— 原第 223 行是 RTC_APP_ArmIn(g_lp_period_s) */
static uint32_t sched_next_wake(void)
{
    uint32_t now = RTC_APP_GetEpoch();          /* UTC 秒 */
    uint32_t tod = (now + 8 * 3600u) % 86400u;  /* 北京时：当天第几秒 */
    uint16_t m   = (uint16_t)(tod / 60u);       /* 当天第几分钟 */

    if (sched_in_window(m))                     /* 窗内：按 period 报下一轮 */
        return (g_lp_period_s > 95u) ? (g_lp_period_s - 95u) : 1u;

    LED_AllOff();                               /* 出窗即灭灯 */
    uint32_t nxt = sched_next_window_start(m);  /* 下一个 on 点（分钟） */
    uint32_t delta = (nxt > m) ? (nxt - m) * 60u
                                : (nxt + 1440u - m) * 60u;
    return (delta < 60u) ? 60u : delta;         /* 与 now 的秒级误差兜底 */
}
/* 唤醒后：进窗 → LED_SetColor(g_sched.led, g_sched.bright)；否则保持全灭 */

注意 −95：现有 period_min 的语义是「睡眠时长」而不是「上报周期」 （挂闹钟挂在收尾序列最末尾，会话本身约 95 s），所以 period_min=1 时真实间隔其实 ≈155 s。 顺手改成减法，才能让「窗口内每 60 s 上报一次」成立。

4. 怎么配：指令与配置存储

{"cmd":"lp_sched","on1":"07:00","off1":"09:00",

                 "period_min":1,"led":"G","bright":255}
{"cmd":"lp_sched_off"}          /* 退回常在线；{"cmd":"lp_cycle",...} 仍是纯周期模式 */
字段含义缺省备注
on1/off1 on2/off2两段高峰窗口（北京时间 HH:MM）07:00–09:00 / 17:00–19:00支持跨零点（off < on 时按次日）
period_min窗口内上报周期（分钟）11 = 每 60 s 上报一次
led / bright窗口内亮哪路、多亮G / 255R/Y/G；亮度 0–255 线性

存储位置

  • 首选普通静态变量：Stop 期间 SRAM 保持，窗口配置天然不丢；只在复位后回到缺省。
  • 要抗复位就写 BKP 寄存器（VBAT 域，BKP->DR1..DR6）：起止时间各存「当天分钟数」（uint16 ×4）+ period/led/bright 各一， 6 个 16 位寄存器够用；写前需 HAL_PWR_EnableBkUpAccess()（RTC_APP_Init() 里已经做了）。
  • 时间有效性：开机若 RTC_APP_GetEpoch() 明显不合理（小于编译日期），说明换过电池/掉过 VBAT ⇒ 先联网跑一次 nettime 授时，授时成功前不要进调度，否则窗口判断全是错的。

8. 坑与注意事项

① 换电池后 RTC 时间会丢。RTC 是 VBAT 域，但主电池就是它唯一的电源来源。开机必须判「时间是否合理」，不合理先联网 nettime 一次；授时成功前不要按窗口调度睡长觉，否则可能一觉睡 12 h 不醒。
② period_min 语义 = 睡眠时长，不是上报周期（真实间隔 = period + 95 s）。窗口内要 60 s 上报就必须先做那个 −95 修正，否则实际是 155 s。
③ 4G 上电浪涌 ≈1.2 A（脉冲）。每圈重新上电都会来一次，VCC 就近并 470 µF 的量不能省；电池侧走线尽量短粗，避免第一圈注网时压降触发模组低压复位。
④ 亮灯窗口建议与高峰解耦。冬天 17:00 天已黑，晚高峰亮灯合理；早高峰 07:00–09:00 是否要亮可另配一段独立时间窗。绿灯 255 净增 20.2 mA，要省电就降到 128（+11.1 mA），亮度是线性的。
⑤ 阴雨天的兜底是电池不是面板。掉到 1 h 日照时全天只剩 138 mAh，本方案日耗 211 mAh 就要吃老本 —— 1000 mAh 有 3.8 天缓冲，够用，但别忘了这条。
