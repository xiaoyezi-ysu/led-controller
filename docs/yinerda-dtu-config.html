二、上电初始化配置序列（dtu.c 状态机逐步对应）

固件每次上电（含硬自愈后）按状态机 PARAMSRC → QUERY_ICCID → SEND_MQTT → SEND_LED → SEND_NTP → SEND_LP → SEND_SAVE → WAIT_BOOT → READY 重走一遍（DTU_FORCE_RECONFIG=1 强制重配）：

#指令作用代码
1config,set,paramsrc,1参数来源设为串口配置_4G_PARAMSRC
2config,get,iccid取 ICCID 作设备 ID；失败回退 config,get,imei_4G_QUERY_ICCID
3config,set,mqtt,1,uart,120,…（24 字段长指令，见下）配 MQTT 通道 1 并持久化_4G_SEND_MQTT
4config,set,led,2关闭模组自身指示灯（省电 + 防光干扰）_4G_SEND_LED，宏 DTU_LED_OFF_MODE=2
5config,set,ntptime,1NTP 对时开关（每 1 h 同步一次）宏 DTU_NTP_HOUR=1
6config,set,lp,0 → config,get,lp 回读上报模组低功耗开关；实测 lp 无效，定 0（常在线满频）宏 DTU_LP_VALUE=0
7config,set,save保存进 Flash，模组自动重启 → 进透传_4G_SEND_SAVE

核心：MQTT 长指令（字段一个都不能错位）

config,set,mqtt,1,uart,120,broker.emqx.io,1883,<ICCID>,,,1,0,0,0,0,<下行sub>,<上行pub>,0,0,0,0,0,0,0,0,0
字段段值含义
mqtt,11配置网络通道 1
uart,120120 s★ 通道心跳包周期 —— 这才是真正的保活（官方最小 60 s）。实测靠它，模组在线待机 59 → 14.6 mA
服务器broker.emqx.io:1883公共 broker，user/pwd 空

sub / pubxiaoyeziUESTC1147/<ICCID> / DTU_Topic1147/<ICCID>宏 MQTT_TOPIC_PREFIX（board_config.h）
尾段 ,0×9will×5 + reg×2 + ipv6 + ssl全部关闭

三、运行期指令（探活 / 自愈 / 授时）

动作指令 / 时序对应实现
退出透传+++（裸发送、无 CRLF、发前静默 ≥1 s、发后等 1 s）dtu_send_raw("+++")，ESC_GUARD_MS=1000
查链路状态config,get,ssta（ssta=4 = MQTT 在线）阻塞式探活 dtu_probe_blocking()，60 s 周期（PROBE_PERIOD_MS）
回透传AT+ENTM（需网络在线；链路断时无害）探活收尾固定发
MCU→服务器心跳每 15 s 一条 {"cmd":"ready",…}HB_PERIOD_MS=15000（低功耗时停发，靠通道心跳 120 s 兜底，省 75% 待机电流）
软重启探活连败 2 次 → config,set,save（模组重走配置）POLL_SSTA / RECOVER 分支
硬自愈软重启 3 次仍败 / 100 s 无像样应答（MODULE_SILENT_MS）→ PA3 断电 3 s → 上电重走初始化 → 再败退避 5 mindtu_hard_recover()，健康判据只认 可解析应答行（g_dtu_valid_rx_ms，TX 悬空噪声不算）
授时不用 config,get,nettime（会卡死命令通道几十秒）；改由服务器下发 {"cmd":"time","epoch":…} 写 RTCmain.c time 指令 + lp_cycle 收尾自动授时，RTC 误差 ≤2 s
噪声忽略上行里 +++ / AT+ENTM 回显是探活透传噪声网页端 / mqtt_watch.py 已过滤

四、实测定案（踩坑记录）

结论细节
lp 指令保不了连接官方手册 #20：config,set,lp,1 只写「进入低功耗」，没有「保持连接」档；「超低功耗休眠」（8~465 µA）不连服务器。本模组 lp,1/lp,0 待机电流无差别 ⇒ 定 lp,0。想省电只能 lp_cycle 整机 Stop（0.22 mA）+ 醒来重连
保活靠通道心跳uart,120 那个 120 s 心跳。停掉 MCU 的 15 s 心跳 + 60 s 探活后，模组在线 59 → 14.6 mA（−75%），连接不掉
nettime 系列在透传模式不回config,get,nettime / ntptime 查询被吞；且 nettime 异步取时会卡死命令通道 ⇒ 弃用，授时走服务器下发
MQTT 字段错位坑,,1,0,… 让 1 落到 pwd ⇒ 主题整体错位、下发丢失。空 user/pwd 必须 ,,,1
探活必须阻塞式旧异步状态机会吃 DTU 1~4 s 迟到应答 ⇒ 误判离线 ⇒ save 重启死循环；改阻塞后（+++ 1.3 s → ssta 1.5 s → ENTM 1 s，重试 1 次）稳定
与整机低功耗的关系lp_cycle 入睡前 V4G 断电（模组完全下线），醒来重新上电重走第二节配置序列 ⇒ 模组「低功耗」不靠 DTU 的 lp，靠整机 Stop
