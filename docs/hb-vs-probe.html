支线 · 心跳与探活：分别是什么，为什么电流不一样

两者都在 Core/Src/dtu.c 里定时触发，但一个走空中接口、一个走串口 —— 这决定了它们对功耗的影响完全不是一回事。

1 · 它们分别是什么

心跳（heartbeat）· 每 15 s

#define HB_PERIOD_MS 15000u
if ((uint32_t)(now - hb_tick) >= HB_PERIOD_MS) {
  hb_tick = now;
  snprintf(hb, sizeof(hb),
    "{\"cmd\":\"ready\",\"id\":\"%s\"}\r\n", my_iccid);
  HAL_UART_Transmit(&UART_4G, hb, n, 200);
}

MCU 往 USART1 写一行 JSON（约 40 字节），模组在透传模式下原样当成一条 MQTT 消息发到上行主题。目的是不让 broker 因会话空闲太久清掉订阅。这是一条货真价实的空口上行。

探活（probe）· 每 60 s

#define PROBE_PERIOD_MS 60000u
dtu_send_raw("+++");            // 退出透传 → 指令模式
// 1s 后
dtu_send("config,get,ssta");    // 查模组网络注册状态
// 读到 ssta=4 → AT+ENTM 回透传 → 补发一条 ready
// 非 4 / 超时无应答 → config,set,save 重启模组

解决的是「假在线」：ssta=4 显示已连服务器，链路其实已经死了。所以要周期性撬开透传、问模组一句「你还活着吗」，顺带具备自愈能力（不行就重启模组）。

5 · 结论

  • 那 +30 mA 全部来自心跳。心跳 ON→OFF：中位 65.31 → 35.20（−30.1 mA）；而探活 ON→OFF（心跳都开）：65.31 → 65.30，等于没变。
  • 探活不改「典型电平」，只制造短促突发。心跳关掉时才看得清：中位 35.20 vs 34.97（几乎相同），但平均 50.31 vs 39.29（+11 mA）、σ 28.11 → 10.93、峰值 145.92 → 65.80 —— 探活每 60 s 触发一次持续十几秒的高功耗窗口，把平均值抬高，中位数不受影响。
  • 两者不叠加。心跳开着时探活的边际成本 ≈ 0：射频本来就被心跳维持在高位，增量被吸收了（第 1、2 档平均只差 1.4 mA，噪声级）。
  • 顺带一个细节：探活收尾时会把 hb_tick 和 probe_tick 一起顶到当前时刻（dtu.c 268–269 行），所以探活还会顺便推迟一次心跳。
工程含义：心跳是真正的空口上行，每 15 s 强制把射频唤醒并保持一段高功耗态，于是把整体电平抬高约 30 mA；探活主要是串口本地交互，代价集中在切模式那一下。所以要降平均功耗，放宽 HB_PERIOD_MS 最有效，动探活几乎没用 —— 探活的价值是链路自愈，不是省电。
