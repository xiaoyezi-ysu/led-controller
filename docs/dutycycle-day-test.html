6 · 口径修正验证（旧脏 / 新净 / 预期）

根因：上一版的睡态 1.03 mA 是 DBGMCU_CR = 0x00000307 造成的测量伪值 —— 它是 OpenOCD 每次 init 写入的调试保活位（DBG_SLEEP|DBG_STOP|DBG_STANDBY），让 Stop/WFI 不停内核时钟：睡态虚增 ≈0.82 mA、Run(WFI) 虚增 ≈0.29 mA，且退出调试器不清除（只有复位才清），所以同一上电周期内所有测点一起偏高。A/B/A 实测 0x307 → 1.042 mA / 写 0 → 0.220 mA / 再连 → 1.042 mA。

7 · 口径与复现

测量链路

  • 电流：安服优 F-11 真值表，串联在供电回路内，38400 8N1，≈10–11 Hz
  • 置态：固件 SEQ 工况引擎（Core/Src/main.c），经 OpenOCD 写 RAM（g_test_cmd + g_test_go）触发，每档切换时把档名与 RTC 秒写进 RAM 标记日志 g_slog
  • 时标：RTC 秒计数（唯一跨 Stop 存活），收尾用中位线性标定 scale
  • 干净口径：每个 OpenOCD 会话末尾都写 mww 0xE0042004 0 清 DBGMCU_CR 并回读确认 —— 否则 OpenOCD 的 init 会把 DBG_SLEEP|DBG_STOP|DBG_STANDBY 置上，睡态虚增 ≈0.82 mA、Run(WFI) 虚增 ≈0.29 mA，且退出调试器不清除（只有复位才清）
  • MQTT：bench/mqtt_watch.py 常驻旁听，落盘 data/mqtt_live.csv
  • 电荷：对采样做梯形积分 ∫I dt，再折算 mAh
