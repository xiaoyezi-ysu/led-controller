1. 结论

断开 R24 后，Stop 模式实测 1.162 mA —— 首次进入 1 mA 量级。
这条通路上 R24（510 Ω）+ LEDB2 蓝灯常亮实际吃掉 ≈ 1.1 mA，是整板静态电流里最大的一块"可拆"负担。 拆掉之后 Run 从 3.47 降到 2.40 mA，Stop 从 2.31 降到 1.16 mA。
两组实测的 Δ 高度一致（−1.08 / −1.15 mA），说明 LEDB2 的实际功耗就是 ≈1.1 mA， 而且它在 Run / Stop 下都一样亮、一样耗。此前文档里估的「≈1.4 mA」略高。

4. 操作踩坑（重要）

⚠️ 进了 Stop 之后，清 SCB_SCR=0 并不能让 MCU 退出 Stop。
WFI 已经在 Stop 里等中断；STM32 的 Stop 只能由 EXTI 唤醒， 内核异常（SysTick 等）唤醒不了它。这块板上唯一可靠的退出方式是 复位 （mklink reset 或按 SW4）。
  • 实测：清掉 SLEEPDEEP 后电流卡在 1.94 mA（既不是 Run 的 2.40，也不是 Stop 的 1.16）—— 正是"已清标志但人还在 Stop 里"的中间态。
  • 往 SCB_ICSR(0xE000ED04) 写 PENDSTSET 触发 SysTick 异常， PENDSTSET 位不被消费（读回仍是 1），也验证了这一点。
  • 另：mklink 的 PATH 会漂。若报 mklink: command not found， 用绝对路径 C:\Users\Administrator\.workbuddy\binaries\python\envs\default\Scripts\mklink.exe。

5. 下一步（要真正 ≤1 mA）

  • 固件化 Stop：现在 Stop 是 SWD 外部注入的。要在固件里真正落实：主循环空闲即 HAL_PWR_EnterSTOPMode()， 并用 EXTI（UART RX 引脚） 做唤醒源——否则进了就出不来。
  • 关掉唤醒抖动：Stop↔唤醒往复是 1.16 mA 里剩下的主要部分。把非必要的周期性中断（TIM3 / SysTick 唤醒节拍）停掉可再降。
  • 量 LDO 静态：CN3142（Iq 3 µA）+ ME6206A33（Iq 8 µA）本身很小，但要核实实测漏电。
  • 接好 F-11 电压通道，拿到真实 VCC 而非假定 3.3 V。
