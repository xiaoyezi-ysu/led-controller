三点值得记：

  • 42.2 mA 是「模组维持 MQTT + 周期发射」的全部代价，占整板 66%。断电后最低电流 19.6 mA、最高只有 25.4 mA —— 模组那一路的突发尖峰（最高 143 mA）全部消失。
  • 断电是可逆的：SWD 写 GPIOA->BSRR（0x40010810 写 0x08）拉高 PA3，模组 16 秒后重新上线（ready 心跳回来），电流回到 63.6 mA。但注意 不能用 MQTT 发 v4g on 恢复 —— 模组断电后 MQTT 收不到命令，必须走 SWD。
  • 断电期间顺手把 dtu.c 的 low_power 写 1，冻结心跳/探活，免得探活超时把状态机带进 WAIT_BOOT 乱跳（探活只发串口命令，不会自己去拉高 PA3，所以断电状态本身是稳定的）。

2 · LED 电流分离（4G 断电后）

4G 一断，σ 从 28.8 掉到 1.3，LED 那十几 mA 终于能从噪声里浮出来。用 SWD 直接写 TIM3->CCRx（红 0x40000434 / 黄 0x40000438 / 绿 0x4000043C）逐档点灯， 每档写后读回校验，采 20 点取中位。

结论

  • 绿灯最费电：255 满亮 +19.2 mA，是红/黄的 2.6 倍。红黄几乎一样（+7.33 / +7.39）。
  • 低亮度非常省：调到 64（占空比 25%）时，红只有 +0.64 mA、绿 +1.92 mA —— 远低于线性的 25%（理论应该是 +1.8 / +4.8）。低占空比下 LED 的平均电流明显低于按占空比折算的值。
  • 三路可以叠加：RGB 全亮 = 三者之和，说明三路 LED 与驱动是独立通路，没有共用的限流环节。
  • 作为对照，4G 上电时用 MQTT 走固件路径点绿灯 255：中和位 67.03 → 84.30（+17.3 mA），和断电环境下测到的 +19.2 mA 量级一致 —— 两种完全不同的点灯方式（固件 MQTT vs SWD 直写寄存器）结果互证。

3 · MCU 进 WFI 睡眠能省多少

状态（4G 已断电，LED 全灭）中位avgσ
MCU 运行（每圈 __WFI()，SysTick 1ms 唤醒）21.7021.861.25
MCU 深度空闲（g_low_power=1，SysTick 挂起）21.5421.490.95

差 0.16 mA，等于没有。原因是这块板的主循环每一圈本来就执行 __WFI()（SysTick 每 1 ms 唤醒一次做事）， CPU 内核已经处在断续工作状态；g_low_power=1 只是把 1 ms 的唤醒也取消掉，能省的动态功耗本来就很小。 21.5 mA 的静态电流主体是外设时钟、传感器与板载电路，不是 CPU 内核空转 —— 所以这条路几乎榨不出东西（对比：4G 模组 42.2 mA、绿灯 19.2 mA）。

4 · 测量手法（全程不改固件、不烧录）

动作怎么做的
4G 断电MQTT 真发 {"cmd":"v4g","state":"off","id":"<ICCID>"}（走固件真实路径），再用 SWD 读 GPIOA->ODR 的 bit3 确认 PA3 真的拉低
4G 恢复SWD 写 0x40010810 = 0x08（BSRR 置位 PA3）。不能用 MQTT，模组断电收不到命令
LED 切换SWD 直写 TIM3->CCRx（红/黄/绿 = 0x40000434/38/3C），每路写后读回校验
冻结周期上报SWD 写 dtu.c 的 low_power（0x20000584）= 1
MCU 深度空闲SWD 写 main.c 的 g_low_power（0x2000033D）= 1 → 主循环 HAL_SuspendTick() + __WFI()
电流读数mklink power-read --port COM11 --json，每档 20 点 × 1 s

5 · 踩到的两个 SWD 写入坑（都会让「看起来成功」的写入静默失效）

坑 1：残留的串口 HIL 锁会让所有写操作失败。
现象：write-ram 返回 Runtime HTTP 500: HIL lock 'transport_usb-serial_COM11' held by pid=37820， 而 read-ram 仍然正常 —— 于是读数看着没问题、写入却全部落空（这一轮第一版测试里 4 个 LED 档电流完全一样，就是这个原因）。
处置：mklink resources release-all（清掉陈旧锁，它显示 alive=False，是已死进程留下的）。之后写入立刻恢复。
坑 2：write-ram 多字节写入会因内部回读校验不一致而整体失效。
实测把 CCR1 写 0xFF 0x00（2 字节）：工具报 Write completed but verification differed，读回仍然是 0000；
改成 1 字节 0xFF：status ok / verified true，读回 ff00 = 255 ✓。
所以这里所有寄存器/变量写入都改成逐字节写（CCR 高字节本来就是 0，亮度 0–255 只需低字节）。 验证过的 1 字节写入：0x40→4000、0xC8→c800、0x01→0100、0xFF→ff00，全部可靠。

6 · 局限

  • 测的是探针 VCC 上的整板总电流，模组 / MCU / LED 混在同一路。想单独测某一路得从硬件上分开供电。
  • 低亮度档（红 64 / 绿 64）的 σ 偏大（2.68 / 6.18），绝对值不如满亮档精确；趋势可信，小数位别当真。
  • 「MCU 睡眠几乎不省电」这个结论只在这块板 + 这套外设配置下成立，不能外推到别的工程。
  • 4G 断电期间固件仍在向 USART1 写心跳/探活（只是没人收），这部分的 MCU 开销没有单独分离。
