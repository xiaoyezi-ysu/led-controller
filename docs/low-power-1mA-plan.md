# 整板电流降到 1 mA 的方案（且不变砖）

> 目标：整板电流 → **1 mA**，且**永不出现"必须手动拉 BOOT0 走 ISP 才能救回来"的状态**  
> 硬件：车牌板 ver2（STM32F103C8T6 + 银尔达 YED_DTU4 / SC7A20H；光伏 → CN3142 → VBAT → 单 LDO ME6206A33 → VCC33）  
> 图表版：`low-power-1mA.html`  
> 依据：`power-consumption-test.md`（四轮实测）+ ST/微盟/如韵数据手册 + **`车牌ver2.eprj2`（09-23 改版后最新图，2026-10-12 确认）**

---

## 🗺️ 路线图：每步方法 → 达到的电流 → 踩过的坑

> **📊 图表版（推荐看这个，纯 SVG 无外部依赖，可离线打开）：`low-power-roadmap.html`**  
> 本 md 保留等价文字版。

### 达成路径（主链 = MCU 侧；旁支 = 4G 模组）

```
主链（4G 断电 · LED 全灭）
  起步 72 MHz Run          ≈22.5 mA（探针原始）
    │ ① L1 关 PLL → HSE 8 MHz 直供 + Flash 0 等待      −11.8 mA（−52%）
    ▼
  8 MHz Run                ≈10.5 mA（探针原始 / 真值≈3.5）
    │ ③ L2 DBGMCU_CR=0x02 + SCB_SCR=0x04 + WFI         −1.16 mA
    ▼
  8 MHz Stop                2.31 mA（F-11 真值）
    │ ④ 断开 R24（拆 LEDB2 常亮 510 Ω）                 −1.15 mA
    ▼
  8 MHz Stop + 拆 R24       1.162 mA  ✅ 1 mA 量级达成（F-11 真值）

旁支（4G 模组，与 MCU 状态正交）
  4G 上电 PA3=1            59.40 mA ──② 关 4G 电源 −55.9 mA──▶ 3.47 mA  4G 断电 PA3=0
```

### 每步一览

| 步       | 方法（怎么做的）                                                                                   | 达到的电流                                     | 省下                 | 风险 / 回滚                       |
| ------- | ------------------------------------------------------------------------------------------ | ----------------------------------------- | ------------------ | ----------------------------- |
| ① L1    | `SystemClock_Config()` 关 PLL，HSE 8 MHz 直供，Flash 0 等待，`HSI_DISABLE`；宏 `CPU_CLOCK_8MHZ` 一行开关 | 72 MHz **22.5** → 8 MHz **10.5** mA（探针原始） | **−11.8 mA**（−52%） | 零风险，注释宏即回滚；不碰 SWD / 选项字节      |
| ② 关 4G  | SWD 写 `GPIOA_ODR` 清 bit3（4 字节 `0x04 0xA4 0x00 0x00`）→ V4G 断电                               | 4G 上电 **59.40** → 断电 **3.47** mA（F-11 真值） | **−55.9 mA**       | 固件下次复位会把 PA3 拉高、4G 自动回 ~60 mA |
| ③ L2    | `DBGMCU_CR=0x02`（保 SWD）+ `SCB_SCR=0x04`（SLEEPDEEP），主循环 `WFI()` 进 Stop                      | Run **3.47** → Stop **2.31** mA（F-11 真值）  | **−1.16 mA**       | 进 Stop 后只能 EXTI / 复位退出，见下表    |
| ④ 拆 R24 | 硬件断开 R24（510 Ω，串在 VCC33 与 LEDB2 之间）；或改由 GPIO 控制                                            | Stop **2.31** → **1.162** mA（F-11 真值）     | **−1.15 mA**       | 改板件；常亮在 Run / Stop 下耗电一样      |

**⇒ 1 mA 量级达成**（距 1.00 mA 还差 0.16 mA，来自 Stop↔唤醒往复抖动 + LDO 静态/漏电）。

> ⚠️ **口径说明**：4G 上电（59.40 mA）与断电（3.47 mA）差 **55.9 mA**，它和 MCU 是**正交**的两个维度，  
> 所以画成旁支而不是链路一步。起点 22.5 mA 是 **4G 已断**时测的（当时还没有 F-11，为探针原始值）。

### ⚠️ 遇到的问题（踩坑记录）与对策

| 阶段   | 问题                                        | 现象 / 代价                                                                                  | 解决方法                                                                              |
| ---- | ----------------------------------------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| ① 调试 | `mklink write-ram` **重建整个 32 位字**，未写字节被清零 | 写 CCR 高字节把 16 位寄存器清 0 → 误判「8 MHz 下 LED 不亮」；写 `GPIOA_CRH` 高字节打断 USART1 → 4G 通信断（42→12 mA） | 多字段寄存器**一次写满 4 字节**，16 位寄存器**只写低字节**；误写后**重新烧录**恢复                                |
| ③ 判定 | 探针 `power-read` 存在 **≈6 mA 零点偏置**且漂移      | 曾把 8.20 mA 当成「无法解释的神秘固定负载」，方向几乎走偏                                                        | 改用 **F-11 真值表**独立互证；每次对比前先测零点，绝对电流 = 读数 − 零点                                      |
| ③ 判定 | 进 Stop 后 AHB/APB 寄存器**整片读 0**             | 一度以为「寄存器被清零 / 固件挂了」，怀疑变砖                                                                 | 认作 **Stop 指纹**（内核私有区 `SCB_SCR`/`DBGMCU_CR`/`SysTick` 仍可读）；清标志后读数立即复原              |
| ④ 收尾 | 进 Stop 后清 `SCB_SCR=0` **出不来**             | 电流卡在 **1.94 mA** 中间态（既非 Run 2.40 也非 Stop 1.16）                                           | **Stop 只能被 EXTI 唤醒**，内核异常（SysTick）无效；唯一可靠退出 = **复位**（`mklink reset` / SW4），复位后未变砖 |
| 全程   | `mklink` 从 PATH 漂没（`command not found`）   | 所有命令失败                                                                                   | 用绝对路径 `...\envs\default\Scripts\mklink.exe`                                       |
| 全程   | 电表 USB 掉线会**切断被测回路**                      | 表一消失，板子立刻断电（`idcode=0x0`、电流退回零点）                                                         | 测完不要随手拔 Type-C；表串在探针 VCC 与板子 VCC 之间                                               |
| 硬件   | LEDB2 + R24 510 Ω **跨 VCC33 常亮，固件关不掉**    | 常亮吃 ≈1.1 mA，1 mA 目标最大的单项拦路虎                                                              | **硬件断开 R24**（或改由 GPIO 控制）                                                         |
| ⑤ 复核 | INA228 的 `raw` **LSB 随自动量程变**，没看档位标签就换算     | LOW 档(78.125 nV)被当成 HIGH 档(312.5 nV) → 反算 R 得 0.4 Ω，误判成「物理电阻 0.408 Ω / 压降 24 mV」         | **按行里的 `LOW`/`HIGH` 标签取 LSB**；取对后 R = **0.1000 Ω**，与固件 `R_SHUNT=0.1f` 一致（见 §15） |

## 0. 结论先说

1. **现在这 22 mA 里，约 21 mA 是 STM32 自己在 72 MHz 的 Sleep 态。**  
   实测 4G 断电 + LED 全灭 = 21.96 mA；数据手册 Sleep@72 MHz = 22 mA（typ）。  
   → **把 MCU 从 Sleep 改成 Stop，这一项直接从 21 mA 掉到 0.014 mA（1/1500）。**  
   这一步单独就把 22 mA 打到 ~1 mA。
2. **「1 mA」有两个口径，必须分开谈**：
   | 口径           | 含义                  | 改完能到                                                   |
   | ------------ | ------------------- | ------------------------------------------------------ |
   | **A 静态待机电流** | 不联网、纯待机，4G 已断电      | **≈ 0.12 ~ 0.2 mA** ✅ 富余                               |
   | **B 长期平均电流** | 含周期性唤醒 + 4G 上线 + 上报 | `≈ 0.15 + 70 mA × T_on / T`，**上报周期 ≥ 25 min 才 < 1 mA** |
3. **前提：必须放弃「4G 常连 MQTT」。**  
   模组只要在网，最低就是 ~~35 mA（心跳关）~~ 65 mA（心跳开）。**「常在线」和「1 mA」在物理上互斥**，没有折中。  
   当前固件的 `{"cmd":"sleep"}` 语义是"MCU 睡、模组保持 MQTT"→ 实测仍是 40 mA，**永远到不了 1 mA**，必须改语义。
4. **不变砖的要点只有一句话**：**不动 SWD 引脚、不写选项字节**。做到这两条，无论固件怎么睡，都能救回来。
   > ⚠️ 反过来：`DBGMCU_CR` 的 `DBG_STOP` 位**不要**在生产固件里开——它让内部 RC 在 Stop 下继续跑，  
   > 既抬高 Stop 电流，又在我们这块板上未必可写（见 §5.3）。救砖靠"开机窗口 + 唤醒窗口 + 复位键"，不靠它。

## 1. 电流被谁吃了（实测 + 数据手册对照）

### 1.1 现状：4G 断电 + LED 全灭 = 21.96 mA

| 项                                    | 电流                 | 依据                                           |
| ------------------------------------ | ------------------ | -------------------------------------------- |
| **STM32F103C8T6，Sleep@72 MHz，全外设使能** | **≈ 21 mA**        | 数据手册 typ 22 mA / max 35 mA（VDD=3.3 V, 25 °C） |
| SC7A20H 加速度计（VCC33 常供电）              | ~0.1 mA            | 待实测                                          |
| PA1 电池采样分压（R5 4.7 kΩ + R13 102 kΩ）   | ~0.03 mA           | 3.3 V / 106.7 kΩ，待确认                         |
| ME6206A33 静态电流 Iq                    | 0.008 mA           | 数据手册 8.0 µA typ                              |
| 4G 模组                                | 0（已切断）             | 实测                                           |
| LED                                  | 0（已全灭）             | 实测                                           |
| **合计**                               | **21.96 mA** ✅ 对得上 |                                              |

> **纠一个之前的说法**：`power-consumption-test.md` 里写"21.5 mA 的主体是外设时钟 / 传感器 / 板载电路"——  
> 不准确。**Sleep 模式下内核时钟被门控，但 HSE + PLL + APB1/APB2 外设时钟 + Flash 全都在跑**，  
> 22 mA 这个数字就是 F103 在 72 MHz 的 Sleep 典型值。**主体是 MCU，就是 MCU。** 这决定了改造方向。

### 1.2 三种低功耗模式（数据手册实测值，供选型）

| 模式                    | 电流        | 唤醒延迟 | RAM/外设           | 调试口      |
| --------------------- | --------- | ---- | ---------------- | -------- |
| Run @72 MHz           | 36 mA     | —    | 全在               | ✅        |
| Run @8 MHz（PLL 停）     | 10 mA     | —    | 全在               | ✅        |
| **Sleep @72 MHz**（现状） | **22 mA** | 0    | 全在               | ✅        |
| Sleep @8 MHz          | 3.5 mA    | 0    | 全在               | ✅        |
| **Stop**（调压器低功耗）      | **14 µA** | 7 µs | RAM 保持，外设停、需重配时钟 | ⚠️ 默认不可连 |
| Standby               | 2 µA      | = 复位 | 全丢，从头初始化         | ❌ 不可连    |

**选 Stop，不选 Standby**：二者只差 12 µA（对 1 mA 目标毫无意义），而 Stop 唤醒不用重新初始化全部外设、  
RAM 保持，且**还留了一条"能被探针看到"的路**。Standby 掉调试口，反而更像"变砖"。

## 2. 目标待机预算（§0 口径 A）

| 项                     | 目标值                     | 怎么做到                       |
| --------------------- | ----------------------- | -------------------------- |
| STM32 Stop + RTC(LSE) | 14 + 1.4 ≈ **0.016 mA** | 进 Stop，RTC 走 LSE           |
| ME6206A33 Iq          | **0.008 mA**            | 器件本身够好，无需换                 |
| SC7A20H               | **0.010 mA**            | 休眠前写寄存器进低功耗/掉电模式           |
| PA1 分压                | **0.030 mA**            | 可选优化：上臂串 MOS 开关            |
| 引脚浮空 / 上下拉漏电          | **~0.02 mA**            | 未用引脚全部配 `GPIO_MODE_ANALOG` |
| 4G / LED              | **0**                   | 断电 / 全灭                    |
| **VCC33 轨合计**         | **≈ 0.08 ~ 0.15 mA**    | ✅ 远低于 1 mA                 |

**电池侧另计（这部分探针测不到，要用真实电池 + µA 表；数值按 ver2 器件的数据手册）**：

| 项                 | 目标值            | 说明                                          |
| ----------------- | -------------- | ------------------------------------------- |
| **CN3142 夜间睡眠电流** | **< 0.003 mA** | 数据手册：输入掉电时自动进低功耗睡眠，**电池电流 < 3 µA**（ver2 实装） |
| ME6206A33 静态 Iq   | **0.008 mA**   | 数据手册 8.0 µA typ（ver2 仅存的一颗 LDO）             |
| 4G 模组断电漏电         | **~0**         | 经 PMOS-Q2（AO3401A）；V4G=0 时栅=源（经 R60），无电流    |
| 电池自放电             | —              | 与电路无关，但决定了超长待机的实际上限                         |

**结论：口径 A 有 ~10 倍余量，1 mA 不是问题。真正的约束是口径 B。**

## 3. 口径 B：含周期上报的平均电流（真正的难点）

### 3.1 公式

```
I_avg = ( I_on × T_on + I_sleep × (T − T_on) ) / T
```

- `I_on` ≈ **70 mA**（4G 注网 + MQTT 连接 + 上报 + MCU 72 MHz；实测 4G 在线档中位 64.16 mA）
- `T_on` ≈ **20 s**（注网 ~16 s + 连接 + 发一包 + 收尾）
- `I_sleep` ≈ **0.15 mA**

### 3.2 算出来是这样

| 上报周期 T     | 平均电流        | 2000 mAh 电池续航 |
| ---------- | ----------- | ------------- |
| 5 min      | 4.81 mA     | ~17 天         |
| 10 min     | 2.48 mA     | ~34 天         |
| 15 min     | 1.70 mA     | ~49 天         |
| 20 min     | 1.31 mA     | ~64 天         |
| **27 min** | **1.00 mA** | **~83 天**     |
| 30 min     | 0.93 mA     | ~90 天         |
| 60 min     | 0.54 mA     | ~155 天        |

**→ 上报周期 ≥ 27 min，整板平均就 < 1 mA。**

### 3.3 两个可以让周期变短的杠杆

- **压缩 `T_on`**：`T_on` 减半，所需周期也减半（10 s → 周期 13 min 即可）。  
  手段：MQTT 会话保持 / 减少注网等待 / 上报完立即断电不等回执 / 关掉 15 s 心跳与 60 s 探活。
- **模组侧 PSM/eDRX**：若银尔达 / 飞思创固件支持，可在两次上报之间让模组进深睡（µA 级）而**不注销**，  
  下次上线从 ~16 s 降到 ~2 s。**需先核实这两套透传固件是否开放该命令**（见 §7）。

> 注意：`HB_PERIOD_MS = 15000` 这档在设计里**必须删掉**。15 s 一次心跳 = 平均 +30 mA（已实测），  
> 电池方案里这条直接让续航从 90 天掉到 1 天。


## 5. 代码骨架

### 5.1 进 / 出 Stop

```c
/* 建议放在 board_io.c 同类风格的位置：直接操作寄存器，少依赖 HAL 模块 */
static void LowPower_EnterStop(uint32_t wake_after_s)
{
  GPIO_InitTypeDef g = {0};

  /* --- 1) 负载全关 --- */
  LED_AllOff();
#if defined(LICENSE_PLATE_BOARD)
  V4G_Set(0);                    /* 4G 断电：这一条贡献 42 mA */
#endif

  /* --- 2) 未用引脚 → 模拟输入（浮空输入是经典的 µA 级漏电源）--- */
  g.Mode = GPIO_MODE_ANALOG;
  g.Pull = GPIO_NOPULL;
  g.Pin  = GPIO_PIN_4 | GPIO_PIN_5 | GPIO_PIN_12;      /* PA4/PA5/PA12 */
  HAL_GPIO_Init(GPIOA, &g);
  g.Pin  = GPIO_PIN_10 | GPIO_PIN_11 | GPIO_PIN_15;    /* PB10/PB11/PB15 */
  HAL_GPIO_Init(GPIOB, &g);

  /* --- 3) 关外设时钟（UART / TIM3 / GPIO）--- */
  HAL_UART_DeInit(&UART_4G);
  HAL_UART_DeInit(&UART_PC);
  __HAL_RCC_TIM3_CLK_DISABLE();
  __HAL_RCC_GPIOA_CLK_DISABLE();
  __HAL_RCC_GPIOB_CLK_DISABLE();

  /* --- 4) 挂起 SysTick（否则 1 ms 中断把 Stop 吵醒 / 抬高电流）--- */
  HAL_SuspendTick();

  /* --- 5) RTC 闹钟唤醒（见 5.2） --- */
  RTC_SetAlarmSeconds(wake_after_s);

  /* --- 6) 进 Stop：低功耗调压器 + WFI --- */
  HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);

  /* --- 7) ★醒来后 HSE/PLL 已停，必须重建时钟 --- */
  SystemClock_Config();          /* 回 72 MHz（或 8 MHz，见 L1）*/
  HAL_ResumeTick();

  /* --- 8) 重建外设 --- */
  MX_GPIO_Init();
  LED_Init();
  MX_USART1_UART_Init();
  MX_USART3_UART_Init();
  HAL_UART_Receive_IT(&UART_4G, &RX_BYTE_4G, 1);
  HAL_UART_Receive_IT(&UART_PC, &RX_BYTE_PC, 1);
}
```

### 5.2 RTC 唤醒（不引 HAL_RTC 模块，照 `board_io.c` 手写寄存器的风格）

当前 `stm32f1xx_hal_conf.h` 里 `HAL_RTC_MODULE_ENABLED` 是**注释掉的**，且 CubeMX 重新生成会覆盖源文件清单。  
所以建议**不启用 HAL RTC 模块**，直接写寄存器（和 TIM3 一样的思路，不怕重新生成）：

```c
/* 备份域 + LSE + RTC 一次性初始化（上电后只做一次，用 BKP 寄存器做"已初始化"标记）*/
static void RTC_LSE_InitOnce(void)
{
  RCC->APB1ENR |= RCC_APB1ENR_PWREN | RCC_APB1ENR_BKPEN;
  PWR->CR |= PWR_CR_DBP;                       /* 解除备份域写保护 */
  RCC->BDCR |= RCC_BDCR_LSEON;
  while (!(RCC->BDCR & RCC_BDCR_LSERDY)) { }   /* ⚠️ 加超时，晶振不起要能兜底 */
  RCC->BDCR |= RCC_BDCR_RTCSEL_LSE;
  RCC->BDCR |= RCC_BDCR_RTCEN;
  /* 等 RTC 同步后写 RTC_CR / RTC_PRLL / 开闹钟中断（EXTI17）*/
}
```

- **前提核查：✅ 已确认**。ver2 原理图（用户 2026-10-12 确认）32.768 kHz 晶振**已贴**（PC14/PC15），  
  RTC 走 LSE，定时精度好，**不需要**退到 LSI 方案。
- **不要用 SysTick/延时循环**做长周期唤醒：那要求 CPU 醒着，省不下来。

### 5.3 DBG_STOP 到底开不开？——**不开**

- RM0008 §31.16.3 说 `DBGMCU_CR`（`0xE0042004`）"可以由调试器写；调试器不支持时用户软件也可以写"。
- **但** F103xC/D/E 的勘误 **2.2.2** 明确写着：`DBGMCU_IDCODE` / `DBGMCU_CR` **只在调试模式下可访问，  
  用户模式下读回 0x00**。C8 是中容量，是否同样受限**需要实测**。
- 即使能写，`DBG_STOP=1` 的语义是"Stop 下用内部 RC 继续给 FCLK/HCLK 供时钟"（RM0008 §31.17 位 1）  
  → **Stop 电流会从 14 µA 显著抬高**，与省电目标冲突。

**所以：生产固件 `DBG_STOP = 0`。救砖能力不靠它，靠 §6 的三级救援。**

## 6. 不变砖：五条铁律 + 三级救援

### 6.1 五条铁律（违反任何一条才真会砖）

| # | 铁律                                                                      | 为什么                        |
| - | ----------------------------------------------------------------------- | -------------------------- |
| 1 | **绝不动 SWD 引脚**：不修改 `AFIO_MAPR` 的 `SWJ_CFG`，不把 **PA13/PA14** 配成 GPIO     | 这是**唯一**会让你"必须拉 BOOT0"的操作  |
| 2 | **绝不写选项字节**：不开读保护 RDP，尤其 **RDP Level 2 = 永久锁死，任何手段都救不回来**               | 唯一不可逆的砖                    |
| 3 | **上电留开机窗口**：复位后先跑 **1~2 s @8 MHz** 再进 Stop                              | 保证任何时刻"重新上电 / 上电瞬间接探针"都能抓到 |
| 4 | **保留唤醒窗口**：每次唤醒都有一段 Run 期（~20 s 级）                                      | 这段里 SWD 必然可用，等于天然的可连接时间片   |
| 5 | **若加 IWDG**：F1 的 IWDG 在 Stop 下继续计数，必须设计成"复位后判断唤醒原因再决定睡不睡"，否则会陷入复位—睡眠死循环 | 这是"看起来像砖"的经典陷阱             |

### 6.2 三级救援（按顺序试，成功率 ≈ 100%）

```
① SWD 直连
   mklink / pyOCD 直接 attach。开机窗口 1~2 s、每次唤醒的 ~20 s 窗口里都能连。
   ↓ 连不上（比如正好睡在 Stop 且时钟全停）
② 复位下连接（connect-under-reset）
   按住板上复位键 SW4 不放 → 探针 attach → 松开 → 立刻擦除/烧录。
   注：本板 SWD 排针 H2 只有 4 pin（VCC33/SWDIO/SWCLK/GND），**没有 NRST**，
       所以只能手按 SW4 配合。
   ↓ 还不行
③ BOOT0 走串口 ISP
   拉高 BOOT0 + 复位 → 系统 bootloader。
   ⚠️ 本板 USART1（PA9/PA10）正好接的是 4G 模组，会抢线 —— 必须先把 4G 断电（V4G=0）
      再下载，否则会失败。所以这条路在这块板上是"能走但别扭"。
```

> 因为 ③ 别扭，**① 和 ② 的可靠性就等于全部**。而 ①② 的可靠性完全由铁律 1、2 保证。  
> **只要不碰 PA13/PA14、不写选项字节，这块板在软件上就不可能被砖掉。**

### 9.5 调试踩坑（重要，`mklink write-ram` 的真实行为）

实测 `mklink write-ram` 对 TIM3->CCR1（16 位寄存器）的行为：

| 操作                                        | 结果                           |
| ----------------------------------------- | ---------------------------- |
| `write-ram --addr 0x40000434 0xFF`（低字节）   | ✅ CCR1 = 0x00FF              |
| 再 `write-ram --addr 0x40000435 0x00`（高字节） | ❌ **CCR1 = 0x0000，整个寄存器被清掉** |
| 单次传两字节 `0xFF 0x00`                        | ❌ `verification differed`，失败 |

**结论：写 TIM3->CCRx 只写低字节**（亮度 0..255 恰好只占低字节）。  
本会话曾因"逐字节分开写"把 CCR 清成 0，误判为"8MHz 下 LED 不亮"，实为工具用法问题。

同理，改 `GPIOA_CRH` 时写高字节会把 CRH 清零 → USART1（PA9/PA10）被打断，  
导致 4G 模组无法通信（表现为模组电流从 42 mA 掉到 ~12 mA）。  
恢复办法：**重新烧录**（`MX_GPIO_Init` / `MX_USART1_UART_Init` 会重建引脚配置）。

> 本节结论同时修正 `debug-summary.md` 附 C 里"一律逐字节写"的说法：  
> **不是"逐字节"就行，而是"只写低字节"**。

## 10. ver2 原理图实测校正（2026-10-12 晚，读 EDA + SWD 实测）

原理图用 `easyeda-eda` skill 直接读出来了（详见 `docs/ver2-netlist.md`：电源树 + 57 条网络 + VCC33 负载清单）。  
下面几条**推翻了前文的若干结论**，以本节为准。

### 10.1 电源拓扑（ver2 真实连接）

- 4G 模组 **挂在 VBAT 侧**：`VBAT → R60 100k → PMOS-Q2(AO3401A) → V4G → 模组 pin7`；PA3 经 R59 1k 驱动 Q5，Q5 拉低 PMOS 栅。
- `U4 = ME6206A33`（微盟，LCSC C161345，Iq **8 µA**）→ VCC33 只给 MCU / 传感器 / LED / 上拉。
- **实测 `VBAT = 3.384 V`**（SWD 手动启 ADC1 读 PA1 分压 R7 100k/R8 220k）＝ 探针 VCC 电压  
  → **探针的 VCC 是接在电池侧（BAT+/VBAT），不是 VCC33**。所以 `power-read` 的读数 = 整板总电流。

### 10.2 4G 模组实测（VBAT 侧，8 MHz 固件）

| 状态                     | 中位电流          | 范围                                   |
| ---------------------- | ------------- | ------------------------------------ |
| 4G OFF（PA3=0）          | **10.37 mA**  | 9.45~12.08                           |
| 4G ON（PA3=1，等 22 s 搜网） | **52.52 mA**  | 19.0~133.3                           |
| **模组自身**               | **+42.16 mA** | 与 72 MHz 时测得的 42.2 mA 一致 → **与主频无关** |


✅ 之前"8 MHz 下 4G 净增 ≈0 mA"是**假故障**：PA3 当时被配成了**模拟输入**，模组根本没上电（见 10.3）。

### 10.3 ⚠️ `mklink write-ram` 的真实语义（第二次踩，务必记牢）

实测：`write-ram --addr A <n 字节>` 会把 **A 所在的整个 32 位字**按写入的字节重建，  
**未写入的其余字节一律被清零**（不是"只改那一个字节"）。

| 操作                                           | 结果                                       |
| -------------------------------------------- | ---------------------------------------- |
| 向 `0x40010801`（CRL 第 2 字节 = PA2/PA3）写 `0x22` | CRL 变成 `0x00002200` —— **PA6/PA7 被顺带清零** |
| 向 `0x40010803`（PA6/PA7）写 `0xAA`              | CRL 变成 `0xAA000000` —— **PA2/PA3 被顺带清零** |

→ 本会话早先 `blink_check` 为了"恢复"PA6 写了 `0xAA` 到 CRL+3，**把 PA2/PA3 抹成模拟输入**，  
导致之后所有"4G 开关"实验都是对着一个没上电的模组在做，白测了一轮。  
**正确姿势：凡多字段寄存器，必须一次写满 4 字节**（如 CRL 目标值 `0xAA002200` → 写 `00 22 00 AA`）。  
BSSR 因为只写 1 位，单字节写反而正好（写 `0x08` 到 `BSRR+2` = 复位 PA3；写 `BSRR+0` = 置位 PA3）。

### 10.4 8 MHz 下 10.37 mA 的构成（4G OFF / LED 全灭）

| 项                            | 电流                | 依据                                                                                            |
| ---------------------------- | ----------------- | --------------------------------------------------------------------------------------------- |
| MCU（Sleep@8MHz，HSE+Flash+外设） | 数 mA              | `halt` 只省 0.34 mA、关 APB/AHB 时钟只省 0.18 mA → **说明大头是 HSE/Flash，不是内核执行**（前文"MCU 只占 0.6 mA"的推断有误） |

## 11. Stop 模式判决实验（2026-10-12 晚，实机验证）

### 11.1 做法

`Core/Src/main.c:234` 的 `__WFI()` 在 `while(1)` 里**无条件执行**（每圈第一件事），  
所以只要 `SCB_SCR.SLEEPDEEP = 1`，下一圈 `__WFI()` 即进 Stop（F1 上 WFI + DeepSleep = Stop，PDDS=0）。  
无 IWDG（`stm32f1xx_hal_conf.h` 未开 `HAL_IWDG_MODULE_ENABLED`），不会被看门狗踢出。

| 步骤     | 操作                                                        |                                                                   |
| ------ | --------------------------------------------------------- | ----------------------------------------------------------------- |
| 生命线    | 先写 \`DBGMCU_CR                                            | = 0x02`（DBG_STOP）→ 实测**可写**，Stop 下 SWD 仍存活 → 可 `mklink reset\` 恢复 |
| 进 Stop | `write-ram 0xE000ED10 04 00 00 00`（SCB_SCR = SLEEPDEEP）   |                                                                   |
| 真值     | 再清 `DBGMCU_CR` 的 DBG_STOP → SWD 立即失联（符合预期）→ 测"生产口径"真 Stop |                                                                   |
| 恢复     | 继电器给下载器断电（COM12），板子同时掉电重启                                 |                                                                   |

### 11.2 实测（探针 VCC ≈ 3.38 V；4G 断电 + LED 全灭）

| 状态                                   | 中位电流         | 相对基线      |
| ------------------------------------ | ------------ | --------- |
| 基线（8 MHz / Sleep / 4G-off / LED-off） | **10.25 mA** | —         |
| Stop + DBG_STOP=1                    | 9.73 mA      | −0.53     |
| **Stop 真值（无 DBG_STOP）**              | **8.20 mA**  | **−2.06** |
| 恢复后基线                                | 10.60 mA     | 已复原 ✅     |

### 11.3 内核确证停住（关键证据）

进 Stop 后读 `uwTick`：**增量 = 0 ms / 1.5 s**（此前 2900+ ms/1.5 s）。  
SysTick 由 HCLK 供时钟，HCLK 一停它就停 → **证明 HCLK 真的断了，MCU 确实在 Stop**，不是"假睡"。

> 注：Stop 下读外设寄存器（如 `GPIOA_ODR`）会读回 0，因为 APB 时钟已关——这是读数假象，  
> **引脚的输出电平实际是保持的**。核心区寄存器（SCB_SCR / DBGMCU_CR）仍可正常读。

### 11.4 结论：那 8 mA 与 MCU 无关（推翻前文分解）

- **MCU(8 MHz) 全部贡献 ≈ 2.06 mA**（内核 + HSE + Flash + 所有外设时钟，全停也就省这么多）。
- **整板仍有 8.20 mA 与主频无关、与 CPU 是否执行无关。**
- DBG_STOP 自身代价 ≈ 9.73 − 8.20 = **1.53 mA**（F1 上 Stop 期间调试逻辑靠内部 RC 供时钟）。

修正后的分解（自洽）：

```
72 MHz：22.48 = 8.20(固定负载) + 14.28(MCU)

### 11.5 这 8.20 mA 无法用网表解释 ⚠️

| **未解释余量**                                 | **≈6.4 mA** |

模组其余脚（TX1/RX1/PB3/PB4/GND）都不构成常供电通路 → **模组在 V4G=0 时确实没电**。

**两个待判假设**：

1. **探针 `power-read` 存在固定偏置**（下载器 VCC 侧内部负载/零点未校）；  
   旁证：用 MCU 的 `VREFINT`(1.20 V) 反推 **VCC33 ≈ 3.18 V、VBAT ≈ 3.185 V**（两者相等 → LDO 处于

2. **板上器件漏电/损坏**：U4 LDO 或 U8 CN3142 或 U6 DW03 内部击穿（**本板历史上就出现过

### 11.6 下一步（决定性，需 15 秒手工）

- 若显示 ~0 mA → 板上真有 ~6.4 mA 漏电，按网表逐个拆：

## 12. 【重大修正】探针 `power-read` 存在 ~6 mA 零点偏置（2026-10-12 深夜实测）

### 12.1 实验：断开目标后读数不为零

把探针从板子上断开（**SWD 无目标**）后测 `power-read`：

| 判据                           | 结果                                                                                  |
| ---------------------------- | ----------------------------------------------------------------------------------- |
| `mklink device-status`       | `"mcu": ""`、**`"idcode": "0x0"`** → 没探到目标芯片                                         |
| `mklink read-reg 0x2000011C` | `Memory read returned 0 bytes … target debug access may be disabled or unavailable` |
| **`mklink power-read`**      | **读数不为 0**，连续 20 次：**中位 5.70 mA，均值 5.69，范围 5.33~6.01**                              |

另一次连续 15 次采样：**中位 6.85 mA，范围 6.11~8.10**。

> **⇒ 探针 VCC 侧在"目标未连接"时仍有 5.3~8.1 mA 的读数。即 `power-read` 的绝对值含一个  
> ≈6 mA 的零点偏置，且该零点会漂移（两次相隔数分钟，从 6.85 变到 5.70）。**

### 12.2 为什么这个结论可信：扣除零点后所有数据自洽

以零点 = 6.0 mA 扣除（4G 断电 + LED 全灭）：

| 实测（含零点）                | 扣除零点后（板子真实） | 独立佐证                                                                                                   |
| ---------------------- | ----------- | ------------------------------------------------------------------------------------------------------ |
| 72 MHz Sleep **22.48** | **16.5 mA** | F103 Run@72MHz 数据手册 typ 36 mA（含 Flash/外设）同量级                                                           |
| 8 MHz Sleep **10.25**  | **4.25 mA** | Sleep@8MHz 数 mA 量级                                                                                     |
| **Stop 8.20**          | **≈2.2 mA** | MCU Stop 14 µA + **LEDB2 常亮 ~0.8 mA** + 上拉 ~0.3 + LDO 8 µA + 传感器 2 µA + 分压 11 µA ≈ **1.1~1.8 mA**，量级吻合 |
| 4G ON **52.52**        | **46.5 mA** | 板子 4.25 + 模组自身 42.16 = **46.4** ✅ 误差 0.1 mA                                                            |

**最后一行是决定性佐证**：4G 上电的整板电流 = 板子本底 + 模组电流 + 零点，三项相加与实测  
**只差 0.1 mA**。若不引入零点，三项相加只有 46.4 mA，**与实测 52.52 差 6.1 mA 无法解释**。

### 12.3 作废的旧结论

- ❌ **§11.4/§11.5 的"整板另有 8.20 mA 与 MCU 无关的神秘固定负载"不成立** ——  
  那 8.20 mA 里 **≈6 mA 是探针读数零点**，剩下 ≈2.2 mA 由 LEDB2 + 上拉等已知项即可解释。
- ❌ "VCC33 上存在约 6.4 mA 无法解释的负载"不成立。
- ✅ 仍然成立的结论（**全部是差值，不受零点影响**）：
  - L1（72→8 MHz）省 **11.8 mA**（−52%）
  - L2（Sleep→Stop）省 **2.06 mA**
  - 4G 模组自身 **42.16 mA**（与主频无关）
  - LED 净增：红 +7.33 / 黄 +7.39 / 绿 +19.18 / RGB +33.59（8 MHz 与 72 MHz 一致）

### 12.4 对"整板 → 1 mA"目标的巨大影响（好消息）

扣除零点后，**Stop 时板子真实电流 ≈ 2.2 mA**，而不是之前以为的 8.2 mA。而这 2.2 mA 的构成：

| 项                                         | 电流                |
| ----------------------------------------- | ----------------- |
| **LEDB2 蓝灯常亮（R24 510 Ω，永久跨 VCC33，固件关不掉）** | **~~0.5~~1.2 mA** |
| I2C/SWD/NRST 上拉（R5/R6/R18/R21）            | ~0.3 mA           |
| MCU Stop                                  | 0.014 mA          |
| LDO 自身 Iq / 传感器 / 分压 / VBAT 侧             | < 0.03 mA         |
| **合计**                                    | **≈1.0~1.6 mA**   |


> **⇒ 结论：`L2（进 Stop）` + `去掉 LEDB2 常亮` ≈ 就能落到 1 mA 量级，  
> 之前认为必需的 `L3（4G 占空比调度）` 可以不做（除非要算含上报的长期平均）。**

### 12.5 测量操作规范（今后必须遵守）

1. **每次功耗对比实验前，先测零点**：断开探针与板子的连接（VCC 悬空），连续读 20 次  
   `power-read` 取**中位数**，作为本次实验的零点。
2. **绝对电流 = 读数 − 零点**；**增量值（Δ）不需要修正**，可直接用。
3. 零点会漂移（本次观测 5.3~8.1 mA），**同一组对比实验应在同一时间段内连续完成**，  
   避免跨时段比对绝对值。
4. 若要得到可信的绝对电流，建议做**已知负载标定**：在 VCC–GND 间接一个已知电阻  
   （如 1 kΩ → 3.38 mA），看读数增量是否等于 I=V/R，以确认偏置是"加法"还是"比例"。

### 13.4 Stop 的确证证据（新）

```
RCC_CR / RCC_CFGR / GPIOA_CRL / GPIOA_ODR  → 全部读回 0x00000000   （AHB/APB 时钟停）

### 14.4 ⚠️ 操作踩坑：进了 Stop 只能靠复位退出

- **唯一可靠退出方式：复位**（`mklink reset` 或按 SW4）。复位后 `RCC_CR=0x35780`、`CFGR=0x05`、`PA3=1` 全部复原，未变砖。

   - 增益 +1.4%：芯片增益误差仅 ±0.05%，**最可能是 0.1 Ω 分流电阻的容差**（1% 档）+ F-11 自身基准误差。
   - 初版说「固件按 0.400 Ω 换算、物理电阻 0.408 Ω」——根因是**把 LOW 档的 `raw` 按 HIGH 档 LSB（312.5 nV）解释**，
     正好差 4 倍。按档位标签取 LSB 后反算 R = **0.1000 Ω**，与固件逐位吻合。**固件没有 bug，是读数时漏看量程标签。**
3. **插入损耗**：0.1 Ω × 60 mA = **6 mV**（0.18%），对 DUT 电流影响可忽略（初版说的 24 mV 作废）。
4. **两个使用限制**：① 串口 **≈1 Hz/通道**（芯片内部其实 19.8 Hz）⇒ 测 3 s 周期振荡仍会混叠，必须稳态测或拉长到 ≥60 s；
   ② 电压通道 `V=0.000 V`（VBUS 未接）⇒ `P` 恒 0。
5. 打印分辨率 **10 µA**（5 位小数），是打印而非芯片的限制（芯片 LSB 3.125 µA）。

## 16. RTC 定时唤醒循环（lp_cycle）——已实现并实机验证（2026-10-13 凌晨）

> 目标：Stop（≈1.05 mA）下用 **F103 内部 RTC 闹钟** 定时唤醒 → 4G 会话上报 → 再睡。
> 无需外部 RTC 芯片：RTC 走 LSE 32.768 kHz（VBAT 域），Stop/复位/掉电期间照跑。

### 16.1 实现方式（固件已烧录）

| 文件 | 内容 |
|---|---|
| `Core/Src/rtc_app.c` / `Inc/rtc_app.h`（新） | **纯寄存器** RTC 驱动：LSE 起振 → BDCR 选 LSE/RTCEN → PRL=0x7FFF（1 Hz）→ 闹钟 = CNT+delay → EXTI Line17 + NVIC。不引 HAL_RTC 模块、不动 hal_conf，**CubeMX 再生成无冲突** |
| `Core/Src/stm32f1xx_it.c` | 新增 `RTC_Alarm_IRQHandler` → `RTC_APP_AlarmIRQ()` |
| `Core/Src/main.c` | 新状态机 `s_lp_state`：session(90s 上报+授时) → closing(+++/CCLK?/ENTM → 挂闹钟 → 关4G → Stop) → sleeping(WFI+SLEEPDEEP)；RTC 唤醒 → `SystemClock_Config()`（**必须**：Stop 退出后 SYSCLK=HSI，不重配则 UART 波特率全错）→ V4G=1 重开会话 |
| `CMakeLists.txt` | 加 `Core/Src/rtc_app.c` |

指令接口（MQTT 下行，订阅主题已含 ICCID）：

```
{"cmd":"lp_cycle","period_min":30}    # 进入循环（1..1440，缺省 30），ACK 后收尾当前会话并入睡
{"cmd":"lp_cycle_off"}                # 退出循环回常在线
{"cmd":"time","epoch":1791827000}     # 服务器授时（写 RTC 计数器，后备通道）
```

会话内自动上报：`{"cmd":"report","wake":"rtc","roll":..,"pitch":..,"sc7_ok":..,"rtc":..}`。

### 16.2 实机验证（F-11 真值，period 临时设 60 s）

| 时段（F-11 180 s 记录） | 状态 | 电流 |
|---|---|---|
| 0–45 s | Stop 睡态（SLEEPDEEP，仅 RTC 闹钟可醒） | **1.03–1.07 mA** |
| ≈48 s | **RTC 闹钟自动唤醒** → 4G 上电注网 | 59–60 mA（13↔80 DRX 振荡 = 已注网） |
| 48–142 s | 会话（90 s 超时 + 收尾 ≈95 s） | ~59.5 mA |
| ≈142 s 起 | 自动收尾 → 再入 Stop | 1.04–1.07 mA |

- 循环连续跑了 ≥3 轮，**无人工干预、没变砖**；SWD 读写全程可用（睡态时外设寄存器读 0 是 Stop 指纹，见 §14）。
- RTC 1 Hz 实测正确（CNT 每秒 +1；SWD 调试手读时注意 **F1 RTC 寄存器有 DIVH/DIVL 在 PRL 与 CNT 之间**：
  CNTH=0x40002818、CNTL=0x4000281C、ALRH/ALRL=0x20/0x24。读 0x14 读到的是 DIVL（0..32767 循环），像乱跳其实是预分频计数器）。
- **授时未生效**：银尔达透传固件不支持 `AT+CCLK`（那是飞思创 AT 固件的指令，§15 手册不适用本模组）；
  收尾的 +++/CCLK?/ENTM 探测每轮都安全失败，不影响定时。授时走 `{"cmd":"time"}` 服务器下发，或换飞思创 AT 固件（`MODULE_FSC_AT`）。

### 16.3 电流账（会话 95 s @59.4 mA + 睡态 1.05 mA）

| 上报周期 | 平均电流 | 备注 |
|---|---|---|
| 30 min（现在） | ≈4.1 mA | 会话占 95 s |
| 30 min（会话缩到 ~50 s*） | ≈2.7 mA | *见下 |
| 2 h | ≈1.8 mA | |

（静态口径 1.03–1.07 mA 不变；只要上报周期 ≥2 h，平均就在 1.5–1.8 mA。）

### 16.4 防变砖设计

- `g_lp_cycle` 是 RAM 变量，**复位/掉电后回到普通在线模式**——固件永远有一条已知好的启动路径。
- 入睡前闹钟必须挂成功（`RTC_APP_ArmIn` 返回 0），否则拒绝入睡、保持在线。
- Stop 睡态可被 SW4 / SWD 复位 / 断电唤醒，不依赖 BOOT0。
- 已知边界：睡态下 MQTT 不可达（4G 断电），"远程唤醒"只能等下一个闹钟；调试用 SWD 写 `g_lp_cycle=0` 或复位。

### 16.5 本轮踩坑（工具）

1. **mklink flash 报 `Failed to write file,status: 17`**（旧 hex 也失败 → 非 hex 问题；SWD 正常、idcode OK；
   root cause 疑似共享 runtime 绑错了工程，409 "Runtime has a different project"）。**解法：改用 OpenOCD 烧录，一次成功**：
   ```bash
   OO="/e/Program Files/stm32tools/openocd/0.12.0-7.1/.content/bin/openocd.exe"
   "$OO" -s ".../openocd/scripts" -c "adapter driver cmsis-dap; transport select swd; adapter speed 1000" \
         -f target/stm32f1x.cfg -c "program build/Debug/xxx.hex verify exit"
   ```
2. **SWD 掉线（idcode=0x0）时 flash 必失败**：先继电器 power-cycle（继电器现在 **COM12**，F-11 回到 **COM4**；`--port` 要显式给）。
3. **F1 RTC 调试读数陷阱**：0x40002810/14 是 DIVH/DIVL 不是 CNT——读 DIVL 得到 0..32767 的均匀分布，极像"寄存器乱跳/时钟错了"。
4. `mklink read-ram --size 4` 单次小读偶发回 0（整段读正常）——回读校验用 ≥8 字节窗口。

## 17. 银尔达 DTU nettime/ntptime/lp 三命令实测（2026-10-13 凌晨）

背景：官方命令手册（yinerda.yuque.com/yt1fh6/4gdtu/zyngfvlgylqny15n）基本命令第 6/18/20 条
声称支持 `config,get,nettime`（读网络时间）、`config,set,ntptime,<1~24h>`（NTP 同步）、
`config,set,lp,<0|1>`（低功耗保持连接）。希望用 nettime 给 STM32 RTC 授时，
替代「服务器下发 epoch」通道。实测方法：SWD 注入 `g_dbg_tx` + 指令模式探针 + F-11 对照。

### 17.1 结论（模组：Air780EPM / YED_DTU4，broker.emqx.io）

| 命令 | 手册 | 实测 | 判定 |
|---|---|---|---|
| `config,get,ssta/netstatus/mqtt/netchaninfo` | ✓ | 指令模式 1.5s 内必回 | ✅ 可用（探活已在用） |
| `config,get,nettime` | 1s 内回 | 指令模式**不回**；透传模式 90s 不回；偶发 ~47s 后补回一条 | ❌ 不可用 |
| `config,get,ntptime` | 1s 内回 | 两种模式均不回 | ❌ 不可用 |
| `config,set,ntptime,1` + save | 持久化 | 已下发并 save，无法回读验证 | ⚠️ 无从证实 |
| `config,set,lp,1` + save | 保持连接低功耗 | get 回 `config,lp,ok,0`（save 前读），save 后无法回读；**F-11 实测电流无差别** | ❌ 无收益 |

### 17.2 关键发现：nettime 会卡死 DTU 命令通道

探针序列 `netstatus→ssta→mqtt→netchaninfo→nettime→ntptime→lp→ENTM` 中，
nettime 之前的查询全部秒回，**nettime 之后的查询全部无应答**（连本來秒回的 lp 也是），
~40s 后通道才恢复。机理：nettime 触发模组异步向网络取时间（手册注明定位类命令最长 60s，
nettime 疑似走同一通道），期间命令通道串行阻塞。**在收尾流程发 nettime 会吞掉 AT+ENTM，
DTU 卡在指令模式、透传数据全断**——已从固件撤除。

### 17.3 电流对照（F-11，60s 均值段，4G 在线空闲）

| 状态 | 中位 | 均值 | 备注 |
|---|---|---|---|
| lp=0（基线） | 59.89 mA | 51.36 mA | 59↔14 mA DRX 交替 |
| lp=1（save 后） | 59.69 mA | 51.13 mA | **无差别** |

注：固件心跳 15s 一次，模组「发完数据 12s 进低功耗」的条件理论上满足，仍未观察到回落，
说明 lp,1 未真正生效（或不作用于 Air780EPM 的该固件版本）。已回滚 DTU_LP_VALUE=0。

### 17.4 对本工程的影响与最终处置

1. **授时**：维持「服务器下发 `{"cmd":"time","epoch"}`」唯一通道；
   `RTC_APP_ParseNettime()` 解析函数保留在 rtc_app.c 备用（固件升级后可复测）。
2. **lp_cycle 不受影响**：定时唤醒是相对闹钟（RTC 计数 + period），不依赖绝对时间。
3. **低功耗路线不变**：在线待机 59 mA 只存在于常在线模式；项目主路径是 lp_cycle
   （Stop 1.03~1.07 mA + 周期会话），DTU lp 本就无关紧要。
4. 固件变更：`_4G_SEND_NTP` 启动态保留（下发 ntptime,1，无害）；探针撤掉 nettime/ntptime/lp
   查询；`LP_CloseAndSleep` 撤掉 nettime（含原因注释，防未来再踩）。
