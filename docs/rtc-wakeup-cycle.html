1. 结论先说

F103 内部 RTC 完全胜任「Stop 定时唤醒」，不需要外部 RTC 芯片。
LSE 32.768 kHz 在 VBAT 域，Stop / SW4 复位 / 掉电期间照跑；RTC 闹钟经 EXTI Line17 唤醒 Stop， 唤醒后重配时钟、4G 上电、上报、授时尝试、挂下一闹钟、再睡——全流程闭环、没变砖、无需人工干预。
授时现状：银尔达透传固件不支持 AT+CCLK（那是飞思创 AT 固件的指令）， 授时探测每轮安全失败、不影响定时。两条路补授时： ① 服务器下发 {"cmd":"time","epoch":..}（已实现）； ② 切 MODULE_FSC_AT 用飞思创 AT 固件（其手册 3.1.22 自带 NTP 授时）。

6. 本轮踩坑

  • mklink flash 报 Failed to write file,status: 17：旧 hex 也失败→非 hex 问题；SWD 正常。 疑似共享 runtime 绑错工程（409 "different project"）。解法：OpenOCD（CMSIS-DAP）烧录一次成功， 命令已记 §16.5；连不目标先继电器 power-cycle（继电器现在 COM12、F-11 在 COM4）。
  • F1 RTC 调试读数陷阱：0x40002810/14 是 DIVH/DIVL（预分频计数器 0..32767 循环）， 不是 CNT！CNT 在 0x18/0x1C、ALR 在 0x20/0x24。读 DIVL 得到均匀随机数，极像"时钟错了"。
  • 睡态下 SWD 读外设寄存器全 0 = Stop 指纹（含 RTC 寄存器接口——RTC 内核在 VBAT 域照跑）， 别误判成掉电/崩溃；RAM 读数在睡态也不可靠，校验变量要等会话窗口。
  • mklink read-ram --size 4 小读偶发回 0，回读校验用 ≥8 字节窗口。
  • 授时：AT+CCLK 是飞思创 AT 固件指令，银尔达透传固件不支持（安全失败，不影响定时）。
