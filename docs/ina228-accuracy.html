1. 结论先说

这块 INA228 板的读数是准的，可以直接替代 F-11 做 mA 量级测量。
零点只有 10 µA（板子断电时实测），增益比 F-11 高 ≈1.4%。 用两个稳态点（2.4 mA / 1.2 mA）拟合得 I_ina ≈ 1.014 × I_true + 0.03 mA， 外推到 58 mA 也只差 0.15% —— 一个很小的固定增益偏差，不校正也能用。
⚠️ 两个使用限制（比精度更重要）：
① 串口只有 ≈1 Hz/通道（固件 millis()>=1000 节流；芯片内部 ADC 其实有 19.8 Hz） ⇒ 测 4G 模组那种 3 s 周期的振荡电流**中位值不可靠**（中位 59.5 mA，但 min 13.6 / max 67.6，σ 17 mA）， 要么拉长到 ≥60 s 取均值，要么在稳态下测。
② 电压通道读 0.000 V ⇒ 只接了串联的 IN+/IN−，VBUS 没接，所以 P 恒为 0.00 mW。要功率得把 VBUS 接到电源上。

2. 它是什么、怎么连的

CH343 转串口的 三通道电流电压监测板，38400 8N1 纯文本输出，每轮打三行 + 一行 I2C 诊断：

[CH1 busA 0x44 INA228 LOW ] V=0.000V I=0.05915A P=0.00mW T=27.6C raw=75710
[CH2 busB 0x40 INA228 LOW ] V=0.002V I=0.00002A P=0.00mW T=26.9C raw=24
[CH3 busA 0x41 INA226      ] V=0.000V I=0.00000A P=0.00mW (no temp) raw=0
[I2C] read fails 0/0/0 | reinit 0/0/0 | frame 10.5ms
通道芯片I²C本次用途读数表现
CH1 busAINA228（LOW 量程）0x44串在被测板电源回路里 —— 就是它测 DUT 电流随负载变化 ✓
CH2 busBINA228（LOW 量程）0x40未接负载恒 ≈0.02 mA（含自身 ~7 µV 零点）
CH3 busAINA2260x41未接恒 0（raw=0）

raw 是 VSHUNT 寄存器计数（20 位有符号）。它的 LSB 随自动量程变，行里带 LOW/HIGH 标签：LOW（±40.96 mV）→ 78.125 nV/LSB； HIGH（±163.84 mV）→ 312.5 nV/LSB。按标签取 LSB 反算分流电阻， 实测全部落在 0.0999 ~ 0.1001 Ω —— 与固件 #define R_SHUNT 0.1f 完全一致。

4. 拟合结果与校正

用 2.395 → 2.460 mA 与 1.162 → 1.210 mA 两个**稳态点**做线性拟合（4G 态那点有混叠，不做拟合权重）：

I_ina ≈ 1.014 × I_true + 0.03 mA      # 增益 +1.4%，零点 +30 µA
I_true = (I_ina − 0.03) / 1.014        # 反算（技能里 --cal 用这个）
外推校验：58.3 mA 处预测 59.14 vs 实测 59.23 → 差 0.15%
  • 零点 +30 µA：在 0.1 Ω 上只是 3 µV，正落在 INA228 自身输入失调 （typ ±1 µV / max ±7 µV ⇒ @0.1 Ω 为 10 ~ 70 µA）范围内 ⇒ 芯片自身，不是接线问题。 独立实测的断电零点 +10 µA 也是同一量级。
  • 增益 +1.4% 最可能的来源：0.1 Ω 分流电阻的容差（1% 档很常见），再叠加 F-11 自身的基准误差。 INA228 芯片自身增益误差只有 ±0.05%，不背这个锅。 不是固件常量错 —— 固件 R_SHUNT=0.1f 与反算的 0.1000 Ω 完全一致。
  • 量具差异可以忽略：0.1 Ω 分流在 60 mA 时压降只有 6 mV（0.18%），对被测板电流的影响远小于 1.4%。
✏️ 更正（初版一处算错）：初版说「固件按 0.400 Ω 换算、物理电阻实际 0.408 Ω」—— 那是因为**把 LOW 档的 raw 当成 HIGH 档解释**（LSB 取 312.5 nV 而非 78.125 nV）， 正好差 4 倍。按行里的档位标签取对 LSB 后，反算 R = 0.1000 Ω，与固件常量逐位吻合。 故「0.4 Ω 分流」相关结论（含 24 mV 压降）作废，实测压降是 6 mV。 根因是我读数时没看量程标签，固件本身没有 bug。
实用建议（优先在板里校，而不是主机侧改数）：
板上固件自带两点标定，系数存 NVS 掉电不丢，屏幕与串口输出都会走它： 
ina228.cmd cmd "cali show"                 # 先看当前系数（本机当前 = 默认 0 / 1）
ina228.cmd cmd "cali zero"                 # ⚠ 只在 DUT 无电流时做
ina228.cmd cmd "cali span 1 0.002395"      # CH1 正通 2.395 mA 参考 → 反算增益
ina228.cmd cmd "cali save"                 # 写入 NVS
参考值建议取 F-11 同态读数（把两台串在同一回路里同时读最干净）。不校正则误差 ≤2%。

6. 已固化为技能

新建 ina228-monitor（~/.workbuddy/skills/ina228-monitor/），纯 pyserial，无外部二进制：

INA="C:\Users\Administrator\.workbuddy\skills\ina228-monitor\scripts\ina228.cmd"

%INA% list                               # 自动找出这块板在哪一路（已验证：COM3）
%INA% read --secs 20                     # 中位/均值/min/max/σ + 档位 + R 自检
%INA% read --secs 30 --ch 1 --cal        # 只看 CH1，并套用 +1.4% 标定
%INA% stream --secs 300 --csv pwr.csv    # 长记录（CSV 含 range / vshunt_mV）
%INA% raw --secs 3                       # 打印原始行排查协议
%INA% cmd "cali show"                    # 给板上固件发命令（命令通道=同一路串口）

主机侧标定系数在 references/calibration.json（gain 1.014 / offset 0.03 mA），默认不启用，加 --cal 才套。
更推荐直接用板上自带的标定（cmd "cali span 1 <Iref_A>" + cmd "cali save"）， 系数写进 ESP32 的 NVS、屏幕和串口一起生效、掉电不丢。
注意 --port 是顶层参数，要写在子命令前面：ina228.cmd --port COM3 read --secs 10。
